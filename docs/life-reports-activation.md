# 用自己的 QQ 邮箱收到日报和周报

目标：后台定时生成真实生活统计，从用户指定的 QQ 邮箱发送到用户已确认的收件邮箱。以实际收件箱验收为准，不以代码上线、模拟或 SMTP 受理作为完成。

## 用户现在只需完成

1. 登录自己的 QQ 邮箱官网 https://mail.qq.com/ 。
2. 在设置中找到“第三方服务”或“账号”下的 SMTP/IMAP 服务，按官网要求完成本人安全验证并生成独立授权码。界面位置以当前官方页面为准。
3. 不要把邮箱密码或授权码发到聊天。授权码留在自己控制的页面，下一步只填入 Cloudflare rin-server 的 Secret。

官方帮助：https://help.mail.qq.com/detail/106/985

不再要求开通 Brevo、购买域名或注册新的群发平台。

## 后台配置（维护人员接入，地址不写公开仓库）

在 Cloudflare 现有 rin-server 的生产设置中添加如下绑定，均选择 Secret；普通变量可能被现有 CI 的 vars 声明覆盖。不得在聊天、代码、日志或静态资源中填值。

| 名称 | 内容 |
| --- | --- |
| REPORT_MAIL_PROVIDER | qq-smtp |
| REPORT_MAIL_PROVIDER_ID | qq-personal-v1；更换发件账户时需单独迁移，不能直接复用旧队列 |
| REPORT_MAIL_FROM | 用户已确认的 QQ 发件邮箱 |
| REPORT_MAIL_TO | 用户已确认的唯一收件邮箱 |
| REPORT_QQ_SMTP_AUTH_CODE | 独立 QQ SMTP 授权码，16位字母；不是 QQ/邮箱登录密码 |
| REPORT_MAIL_VAULT_KEY | 独立安全随机32字节、标准base64的密钥；不得复用其他Secret，已有有效密钥不轮换 |
| REPORT_MAIL_ENABLED | 初次保持false；通道配置和准备核验后设true。该后端门不代替站内收件验证及用户启用 |

不需要 MAIL_API_KEY 或 WEBHOOK_SECRET。不要删除其他业务Secret。切换曾真实发信的提供商必须先暂停/对账；当前没有真实邮件发送，仍不重放未知任务。地址或账户标签变化会计算不同的队列提供商标识，旧queued任务暂停，不把旧消息绑到新地址重发。

## 由维护任务完成

- 固定 smtp.qq.com:465 和隐式TLS，平台验证服务器证书；不开启自定义主机、明文、STARTTLS降级或25端口，不读收件箱。
- 启用网站收件验证和用户明确同意；北京时间日报08:00、周一08:00周报，周报合并日报，避免重复两封。
- 跟踪持久claim和日预算，SMTP返回DATA后的250才是accepted；连接丢失/超时/结果丢失为unknown，保留准入且不自动重发。
- QQ SMTP没有本系统已接入的可信送达/退信回调，界面明确显示此限制；不能声称自动退信抑制、送达或已读。需要核对收件箱/垃圾箱及QQ退信，必要时手动暂停。不增加读取私人邮箱权限来伪造自动对账。
- 发送一份正常真实报告并核对实际收件。AI不可用仍保留统计版，已有DeepSeek unknown不重放、不退预留或额外付费探测。

## 验收界限

隔离SMTP流与临时D1通过不代表QQ授权码有效、Cloudflare到QQ实际连通或Outlook收件成功。真实通道配置之前保持关闭，不能把本开发阶段宣称为已收到报告。
