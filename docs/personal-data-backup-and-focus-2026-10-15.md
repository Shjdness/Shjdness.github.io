# 私人数据备份与待办专注关联

## 本次交付

- `GET /life/backup` 只向已认证且有 Life 权限的账号返回该账号数据，响应标记 `no-store`。导出文章及日记、评论与标签、Life 待办/便签/每日事项/习惯、番茄钟、RSS 订阅和阅读记录、外观设置。排除账号令牌、访问 IP、RSS WebSub 密钥和上传图片二进制。
- Life 首页可以设置口令、下载浏览器本地加密的 JSON 文件，也可在本地解密并验证账号、表清单、行数和 SHA-256。加密使用随机盐、PBKDF2-SHA256 和 AES-256-GCM。口令不发送给服务端。存在待同步操作时拒绝导出，避免误把云端旧状态当成完整备份。
- 待办可以一键带入番茄钟；专注记录保存待办引用和当时任务名。计时完成时先将记录写入本机队列，再推进计时状态；队列写入失败会显示重试提示。待办删除后专注历史保留，关联置空。离线创建的待办按 `clientKey` 关联，待办写入失败时关联专注留在队列等待重试。专注写入按账号和 `clientKey` 幂等。
- 进行中的番茄钟状态按账号隔离保存。旧版未标记账号的浏览器计时状态无法安全归属某个账号，因此不会自动显示或迁移；已写入云端的历史专注记录不受影响。

## 恢复边界

- 当前提供**加密导出及文件完整性验证**，尚无面向生产数据库的自动导入/合并。文件内有可用于人工恢复的完整行和记录 ID；在恢复程序经过空库演练及冲突测试之前，界面不会自动覆盖现有数据。
- 浏览器导出是跨多表读取，运行期间若其他设备同时写入，可能不是同一瞬间的数据库快照；SHA-256 证明导出后的文件内容未变，不能证明各表之间没有并发变更。执行重要备份时应暂停其他设备写入，并核对日记、待办、番茄钟数量。
- 上传图片文件不在 JSON 中。图片需依靠现有对象存储的独立备份。丢失口令无法解密文件；文件和口令应分开保存。
- D1 Time Travel 迁移前书签用于全库回退，书签出现在私有部署日志；它与用户下载的个人数据文件用途不同。

## 上线和验证顺序

1. 先通过本地 TypeScript 编译、Vitest、迁移回放、前端生产构建及 Worker 打包。
2. 部署流程在迁移 0022 前读取 D1 Time Travel 书签，随后执行加列及索引迁移，再部署 Worker；失败时不得继续前端发布。
3. 检查未登录 `/life/backup` 返回 403；用所有者账号导出，并确认日记、待办、番茄钟条数及文件本地验证结果。需要再确认另一受信任账号只能看到自己的记录。
4. 前端发布后从待办进入番茄钟，完成一次专注，确认待办累计分钟数；再验证离线创建待办、恢复网络、队列清空后的关联和重复提交幂等性。

## 后续恢复方案

先在隔离数据库对真实导出格式做恢复预演：校验版本及账号、列出新增/相同/冲突记录数量、对待办及日记按稳定 ID/`clientKey` 做合并，处理外键顺序，最终比对各表行数和内容摘要。通过后才开放生产导入；覆盖或删除应单独确认并保留回退书签。
