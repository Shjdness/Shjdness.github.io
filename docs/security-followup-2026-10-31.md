# 安全复查与恢复推进方案

2026-10-31。基线 ec60395，本轮是定向源码复查与一项恢复加固，不是新做了全量渗透测试。

## 当前判断

写作载入、保存回调和提交前门槛已有连续修补。继续检查发现：加载失败后缺少原页重试，重开页面又不能保证旧未保存稿恢复。本轮补原页重试，并复用首次编辑的逐字段修订点；不能在每次重试时重置基线，否则重试前输入会被当作未改动。云端载入使用未计入人工修订的存储 setter，防止部分写入失败后，把已经载入的云端字段误当作人工编辑而跳过修复。

现有 Worker setup 仍要求 JWT secret，调用独立 authenticate；没有更改会话或权限。上传仍有单图 5 MiB 检查与格式识别，但 StorageService 没有累计上传预算，S3 send 也未设置本路由专用的截止时间。本轮没有向生产发上传探针。

后续检查已为写作原记录 GET 增加 20 秒截止和卸载取消，超时进入保留稿件的手动重试流程。这不包括上传或写入请求，也不表示所有 API 都已具备截止策略。

## 剩余风险与顺序

| 顺序 | 已知边界 | 下一步与验收 |
| --- | --- | --- |
| 1 | 写作 id/new 全局本地缓存缺少账号归属；入口门槛不等于本地加密。 | 完整账号命名空间、旧稿显式确认、只复制不删除的恢复副本及校验；测试断电/存储失败、跨账号、取消恢复，不能默认认领旧稿。 |
| 2 | 新建响应的 ID 只留在当前组件；页面还没有持久采用后台 clientKey 回执。 | 账号隔离后持久化 nonce、原始请求快照与 createdAt；跨标签页领取、丢响应、重载、冲突、删除与备份恢复都要测试。结果未知时不擅自换键重建。 |
| 3 | 私密页面鉴权没有自动保护 StorageService 返回的公开图片链接。 | 设计私有对象与短时授权，验证记录所属人、缓存和过期；先新上传后迁移，保留旧引用恢复路径，不直接关公开桶导致破图。 |
| 4 | 七天令牌通过可读 Cookie 发送 Bearer，完整会话撤销和同站 HttpOnly 方案尚未实施。 | 先验证同站域名、兼容期、CSRF、撤销与离线账号命名空间，再切换。不要直接对 github.io/workers.dev 强推跨站 Cookie。 |
| 5 | 累计上传成本与 SDK 请求持续时间仍缺少独立约束。 | 先采样实际上传次数/字节/失败成本，设计可配置的每账号与总预算、明确重试时间和有界超时；仅记计数，不记正文、令牌或图片内容。预算含计量自身成本，保留交互写入余量。 |
| 6 | 开发工具依赖告警、完整 CSP、私密媒体及字段加密仍有后续工作。 | 兼容升级与构建验收后逐项发布；CSP 先验证编辑器/公式/图表。独立密钥、版本/AAD、双读及隔离恢复完成后再迁移生产正文。 |

旧 R2 公开配置删除仍是用户暂缓的外部事项。本轮没有重新读取内容、绕过权限、换凭据或尝试删除。加密新数据不能撤回旧公开副本；恢复操作能力后单独处理。

## 发布边界

本轮只发布写作加载失败后的原页恢复入口；不调整主页面布局、API、用户 ID、生产内容或 RSS 每日调度与预算。只有失败时显示重试按钮。原记录未成功载入时继续禁止提交，成功后沿用既有保存流程。

回归包含首次失败后的重试前/期间输入、部分缓存写入失败后原类型恢复、身份变化、迟到响应以及原有备份/离线功能。发布后只核对公开资源和 API 健康，不在生产创建测试数据。具体测试总数、提交与发布状态见本聊天工作区 outputs/security-maintenance-2026-10-31/原页载入重试验收.md。

生产加密迁移、密钥轮换、域名/会话切换或私密媒体批量迁移须先准备隔离验证、备份恢复及可审阅方案，再对确需批准的动作申请；不以本文件代表已经完成这些改造。
