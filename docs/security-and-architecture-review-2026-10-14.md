# 第二阶段：结构与安全审查（2026-10-14）

## 系统边界

```text
浏览器（GitHub Pages / React）
  ├─ 公开 Blog、登录回调、Private Life 本地 IndexedDB 与同步队列
  └─ Authorization: Bearer → Cloudflare Worker / Elysia
       ├─ GitHub OAuth、访客码、角色判定
       ├─ Blog / Life / RSS API → D1
       ├─ 图片上传 → R2/S3
       └─ YouTube 官方 Feed / WebSub
GitHub Actions → 构建 Pages、迁移 D1、部署 Worker、定时 RSS 补偿同步
```

信任边界：浏览器与公网请求均不可信；`OWNER_GITHUB_ID`、OAuth/JWT/访客码/RSS/R2 凭据只应存在于部署密钥；D1 记录必须按用户授权；RSS URL 与上传内容属于外部输入。GitHub Pages 为公开静态站，打包进去的任何值都视为公开。

## 本轮检查和已修复问题

| 优先级 | 发现 | 处理 | 验证 |
| --- | --- | --- | --- |
| 高 | OAuth 回跳地址来自未校验的 `Referer`，登录令牌进入查询串 | 固定为 `FRONTEND_URL` 的 HTTPS Origin；令牌置于片段并由回调页立即移除；响应禁止缓存和 Referer | 纯函数测试、类型检查、部署后 OAuth 入口冒烟测试 |
| 高 | JWT 没有 `exp`，旧令牌长期有效；测试环境分支跳过验签 | 新令牌七天到期，验证时拒绝无到期字段的旧令牌；移除跳过验签分支 | 类型检查、登录后人工复核 |
| 高 | 私密文章的评论读取和写入未检查文章可见性 | 与文章读取共用 `canReadFeed` 判定，拒绝不存在或无权访问的目标 | 类型检查及权限函数测试 |
| 高 | Vite 将整个环境对象注入公开前端 | 仅允许五项公开配置进入浏览器包 | 生产构建；部署时检查产物 |
| 中 | CORS 对任意来源开放且设置凭证模式 | 仅允许配置的前端 Origin，关闭凭证式 CORS，限定 HTTP 方法 | 类型检查、部署后预检检查 |
| 中 | 图片上传信任用户提供的文件扩展名和 MIME | 按字节识别 PNG/JPEG/GIF/WebP/AVIF，服务端生成 SHA-256 文件名和类型，拒绝 SVG/HTML | 格式测试、类型检查 |
| 中 | YouTube URL 抓取自动跟随重定向，可离开可信域 | 限制输入路径、HTTPS 域名、端口和凭证；逐跳验证目标 | URL 边界测试、类型检查 |
| 中 | Actions 部署/同步工作流未声明最小权限 | 将 `GITHUB_TOKEN` 设为仅仓库读取 | 工作流语法及部署结果 |

## 遗留问题与下一步方案

1. **Markdown HTML**：目前文章渲染启用了 `rehypeRaw`，但没有配套 `rehype-sanitize`。应先盘点现有文章中的 HTML/嵌入，再引入允许清单与回归样本，避免破坏合法内容。参见 [react-markdown 安全说明](https://github.com/remarkjs/react-markdown#security)。
2. **数据库恢复**：迁移前已有 D1 Time Travel 恢复书签；这不是独立的长期离线备份。制定加密导出、保留周期与恢复演练，且不得把私人数据放入公开 Actions artifact。
3. **Worker 依赖注入**：`typedi` 的全局 Container 在请求期间写入环境和数据库句柄，应改为请求局部上下文，防止并发请求相互覆盖；需要路由级并发回归测试。
4. **依赖与供应链**：锁文件中的框架版本较旧，需在能访问包公告与注册表时审计可利用漏洞，再逐组升级并做端到端回归。Actions 第三方动作应固定完整提交 SHA。
5. **前端体积**：本轮生产构建主包约 2 MB，部分 Mermaid 图表分包约 1.4 MB。拆分文章渲染与大型图表入口、按需加载，然后比较首屏加载量与路由切换体验。
6. **运行监控**：增加无密钥的公开接口冒烟检查、私密接口未登录返回码检查、部署后人工验证 Owner/访客登录和 Life 同步。勿在日志记录 OAuth 状态值、令牌或访客码。

## 验证边界

本轮执行本地单元测试、前后端类型检查、前端生产构建和公开接口的非破坏性检查。没有对生产账户进行密码猜测、流量冲击、数据导出或真实越权写入测试；因此这份审查不是渗透测试合格证明。上线后需由账户持有人重新登录一次，并确认写作、图片上传和 Private Life 同步。
