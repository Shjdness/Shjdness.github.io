# 第二阶段：结构与安全审查（2026-10-14）

## 系统边界

```text
浏览器（GitHub Pages / React）
  ├─ 公开 Blog、登录回调、Private Life 本地 IndexedDB 与同步队列
  └─ Authorization: Bearer → Cloudflare Worker / Elysia
       ├─ GitHub OAuth、访客码、角色判定
       ├─ Blog / Life / RSS API → D1
       ├─ 图片上传 → R2/S3
       └─ YouTube 官方 Feed / WebSub
GitHub Actions → 构建 Pages、迁移 D1、部署 Worker、定时 RSS 补偿同步
```

信任边界：浏览器与公网请求均不可信；`OWNER_GITHUB_ID`、OAuth/JWT/访客码/RSS/R2 凭据只应存在于部署密钥；D1 记录必须按用户授权；RSS URL 与上传内容属于外部输入。GitHub Pages 为公开静态站，打包进去的任何值都视为公开。

## 遗留问题与下一步方案

1. **依赖告警**：已启用 GitHub Dependency graph 与 Dependabot alerts，初次扫描出现 12 条开放告警，涵盖 Drizzle、Elysia CORS、i18next 后端、XML 解析器，以及 Vite/Vitest/Turbo 等开发工具。当前代码使用固定数据库字段、不用动态 SQL 标识符；CORS 改为应用自己逐字比较 Origin；XMLBuilder 未使用，i18next 语言固定为 `zh`。这些限制降低对应利用条件，但不能视为已升级依赖。下一轮按运行时库、构建工具分组升级，并在每组后跑类型检查、构建和线上回归。详见仓库 [Dependabot 告警](https://github.com/Shjdness/Shjdness.github.io/security/dependabot)。Actions 第三方动作也应固定完整提交 SHA。
2. **数据库恢复**：迁移前已有 D1 Time Travel 恢复书签；这不是独立的长期离线备份。制定加密导出、保留周期与恢复演练，且不得把私人数据放入公开 Actions artifact。
3. **Worker 依赖注入**：`typedi` 的全局 Container 在请求期间写入环境和数据库句柄，应改为请求局部上下文，防止并发请求相互覆盖；需要路由级并发回归测试。
4. **本地私人数据**：Life 的 IndexedDB 缓存和可由 JavaScript 读取的登录令牌仍依赖浏览器同源保护。后续应评估专用站点域名与 HttpOnly 会话方案，以及多账户或共享设备上的缓存隔离和退出清理，改动前需确保未同步的离线记录不丢失。
5. **图表体积与兼容性**：文章包和 Mermaid 高级图表分包仍较大；按实际使用情况继续拆分。HTML 允许清单可能过滤旧文章中的自定义嵌入，需盘点旧内容并为合法嵌入设计受限组件。
6. **运行监控**：已增加公开接口、私密接口未登录和 CORS 的部署后冒烟检查；仍需账户持有人验证 Owner/访客登录、图片上传和 Life 同步。勿在日志记录 OAuth 状态值、令牌或访客码。

## 验证边界

本轮执行本地单元测试、前后端类型检查、前端生产构建和公开接口的非破坏性检查。没有对生产账户进行密码猜测、流量冲击、数据导出或真实越权写入测试；因此这份审查不是渗透测试合格证明。上线后需由账户持有人重新登录一次，并确认写作、图片上传和 Private Life 同步。

## 2026-10-15：账号拆分事故与恢复

上线后发现旧版 OAuth 曾把数字 GitHub ID 写入 D1 的 TEXT 列，得到带 `.0` 的账号标识；新版本标准化为整数的字符串后，又新建了同一 GitHub 身份的账号。旧账号的 5 条待办与 12 条日记仍在生产库，新账号另有 1 条日记。它们没有被删除，而是分别绑定到了两个用户 ID。

迁移 0021 在核对新账号除文章外没有其他私人记录后，将那篇新日记归回原账号，并保留退役账号行用于审计。生产查询确认原账号有 5 条待办和 13 条日记；网站重新登录后，同步完成的待办页显示 5 条，日记页显示 13 条。迁移前取得 D1 Time Travel 书签；该恢复窗口仅保留七天，仍需独立加密备份。

OAuth 现在识别旧版 `.0` 标识，避免其他旧账号再次分裂。Private Life 的 IndexedDB 缓存及新离线队列按令牌中的账号 ID 分区；旧版没有账号标识的离线队列原样保留，页面提示待核对，且不会自动向任何账号提交。登录回调会完整重载应用，防止旧账号资料短暂显示在新会话中。此分区解决的是界面误展示和错账号同步，不等同于对同源脚本或设备使用者加密本地数据。

## 2026-10-15：依赖与构建链加固

在独立的依赖解析目录中升级，再将通过验证的锁文件纳入仓库。运行时依赖升级为 fast-xml-parser 5.11.2、i18next-http-backend 4.0.3；开发依赖升级为 Vitest 4.1.11、Vite 6.4.4、React SWC 插件 4.3.3、Turbo 2.11.8。以文本 `bun.lock` 取代旧二进制锁文件，固定 Bun 1.4.3；Turbo 配置迁移到 `tasks`。Elysia 固定在已验证的 1.1.5，避免其宽松版本范围在重装时解析到不兼容的 1.4 系列。

升级 Elysia 与 CORS 插件的组合尝试导致大量前后端路由类型错误，因此未纳入部署。现用 CORS 1.0.2 仍有公开告警，但应用使用逐字比较的 Origin 回调，避开告警中的域名子串匹配路径；部署后必须继续检查允许来源和恶意来源的预检响应。后续要升级 CORS，需连同 Elysia 和 Eden 路由类型做单独迁移与回归。

本地验证：24 项单元测试通过；服务端类型检查、Turbo `check`、前端生产构建、Wrangler Worker 离线打包通过。新版 SWC 在受限 Windows 沙箱的原生模块缓存目录被 ACL 拦截，正常权限下构建成功。离线打包使用示例配置，不代表已验证所有生产密钥和外部服务。部署后仍需核对 GitHub Actions、公开接口、私有数据读取及 Dependabot 告警变化。

尚待处理：独立加密数据库备份与恢复演练；将全局 `typedi` 环境/数据库句柄改为请求作用域；会话 Cookie 与本地私人缓存保护；第三方 Actions 固定完整提交 SHA；CORS/Elysia 兼容升级。这些需要分阶段迁移和线上回归，不应仅凭静态检查认定完成。

线上回归发现日记页加载失败。排查构建产物确认，Turbo 2 默认未向 Vite 传递 `API_URL`，使前端包将请求发往浏览器本机 `http://localhost:3001`；待办页仍可显示本地缓存，掩盖了网络故障。已在 Turbo `build` 任务声明五项公开环境变量，令其传入构建并参与缓存键；Pages 流水线增加产物中的真实 API 地址检查。首次诊断时曾回退 Drizzle 到原先兼容的 0.30.10，但回退后故障仍在，因此不能将此故障归因于 ORM；高危 Drizzle 告警仍未清除。后续应为真实 D1 关系查询补充集成测试，再逐步升级 ORM。此事说明本地缓存、单元测试和静态构建不能替代生产私有路径的冒烟验证。
