# 持续安全维护检查点

本文件是长期任务的项目检查点，避免重复扫描和无变化发布。任务附着当前聊天，每小时检查一次；实际运行依赖本机项目、应用、权限及可用额度。调度不是额度恢复事件订阅，不购买额度或自动使用重置券。

## 工作约束

- 保留页面布局、HTTP API、用户 ID 和未来模块扩展能力；不清理日记、待办、RSS 收藏已读、标签、离线队列或 IndexedDB。
- 一个周期优先处理一个有证据的小范围问题，按风险、可兼容性与恢复成本排序。额度少时轻量核查并保存检查点；未变化时不重复全量构建、部署或旧风险报告。
- 每小时唤醒不代表每小时全量扫描：没有代码或风险变化时，公开健康探测最多每六小时一次，依赖在线审计通常每天一次；发布失败、新公告或相关代码变化时再增加对应验证。存在待办时优先推进待办，而非重复证明旧版本正常。
- 兼容修补自动测试、审阅、提交 main，并核验既有 CI 与线上只读状态。已有未提交工作不得覆盖；高影响改动先在隔离环境准备可审阅方案。
- 生产加密迁移、密钥轮换、权限扩大、域名/会话切换和私密媒体批量迁移要有恢复路径；不绕过工具审批或提取凭据。旧 R2 公开配置对象删除已由用户暂缓，不能重复尝试绕过权限。
- 不在生产生成测试数据、不爆破、不做压力扫描、不发送真实测试通知。不宣称零漏洞。

## 本轮账号隔离修补

文章创建的重复检测原先查询所有账号的标题或正文。已改为当前 uid 范围；避免通过创建是否被拒绝来探测另一账号私密内容是否存在。新增隔离 SQLite 集成场景：跨账号相同标题、相同正文可各自创建；同账号仍拒绝重复；协作者不能直接读取 Owner 的日记。没有生产内容或 schema 迁移。发布结果以该提交 CI 与本聊天最新验收文件为准，不以本段“已改”为已上线证明。

## 后续队列

1. 文章与标签创建/修改的事务一致性及可选幂等操作键，先做失败注入和兼容设计，避免部分成功后重试产生歧义；不要直接添加唯一约束清理旧记录。
2. 上传资源预算与滥用边界；先采样实际用量，避免随意设过小限制影响正常上传。
3. 开发工具告警；优先兼容升级，跨主版本需要 CLI、构建和测试适配，不强制覆盖来隐藏告警。
4. 同站域名、HttpOnly 可撤销会话、完整 CSP、边缘限流及私密媒体授权；涉及部署与访问边界，先准备方案。
5. 独立密钥的字段加密、可选本地保险箱、异地备份恢复演练；保留原记录和离线队列，先解决密钥保管与恢复责任。
6. 访客登录计数保留期和安全事件摘要，保持有界成本，不记录口令、令牌或正文。

## 外部阻塞

旧 R2 对象删除、私有媒体桶权限、独立域名与密钥管理需要相应账号能力；既有权限不足时保存设计并转做独立项目，不不断重试。生产 Owner 浏览器会话未在此前轮次在线，不得将公开页面验收等同于私密数据完整性验收。
