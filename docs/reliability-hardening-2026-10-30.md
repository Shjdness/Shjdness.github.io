# Reliability hardening — 2026-10-30

## Scope and compatibility

Keep the current Blog/Life UI, hosting, account identities and HTTP API routes. No content cleanup, database replacement or IndexedDB reset is included. Stage one migration 0026 only adds a budget table, visit index and note revision column. Existing note, todo, RSS identity, reading and starred records remain in place. The deployment records a D1 Time Travel bookmark before SQL migrations and compares original note fields in memory; contents are never printed. Stage two below upgrades dependencies without adding a database migration.

## Implemented controls

- **Private configuration:** copy `server.config.json` into private D1 `info`, verify the private record, then request legacy-object removal using the existing Cloudflare deployment identity. When that identity lacks R2 access, preserve through the same owner-controlled HTTPS source used by the old Worker; do not request new permissions. Subsequent reads and saves use D1. A failed preservation stops publication. Legacy cleanup denied with 403 is explicitly reported as unresolved, allowing independent reliability fixes to ship. Secret updates use stdin rather than shell arguments.
- **RSS budget:** atomically reserve `24 × changed items + 16` units per batch in a durable UTC-day counter, shared by history, feeds and push. History stops at 25,000 reserved units; daily/push stop at 40,000, leaving feed headroom. Failed reservations remain reserved. This conservative envelope covers item/index/monitoring overhead; it is not an account-wide D1 usage meter or an availability guarantee for unrelated jobs. D1 free daily limits reset at 00:00 UTC (08:00 Beijing).
- **Scheduling:** one daily refresh at 00:17 UTC; history checks after successful daily sync and skips installation/import when all histories are complete. Code deployments no longer trigger history imports. Quota pauses stop retries and source fan-out.
- **Foreground preservation:** hard D1 quota failures return structured 503/Retry-After. The account-scoped local queue stays intact and pauses until reset. An RSS-only budget pause does not pause private-data writes.
- **Conflict acknowledgement:** `saved:false` never removes a queued note. Notes use an atomic revision comparison; conflicts show both versions and require a choice. The original local item is archived before resolution. IndexedDB writes are acknowledged only after transaction commit, with cross-tab queue serialization where Web Locks is available.
- **Public request cost:** article-list cache is memory-only, 60 seconds and 128 entries, with bounded pagination/type inputs. View recording has per-isolate burst deduplication plus its own durable 8,000-unit/day budget (8 units per record). Visit failures do not prevent article reads; historical counts remain, but repeated views can now be sampled rather than counted individually. SQL aggregation replaces loading full visits, notes and unread lists where applicable.
- **Request handling:** request-scoped JWT verification requires expiry and HS256, retains existing role checks and tokens. Upload authorization occurs before multipart parsing. Best-effort per-isolate burst limiting, declared body-size bound, no-referrer/nosniff headers and authenticated-response no-store are added. These are not a distributed WAF or a streaming body-size enforcement layer.
- **Backups:** format v2 includes scoped writing-tag options, while v1 encrypted imports remain supported.

## Future module contract

1. Keep authorization per request and owner scoping in every private query; do not cache identities globally.
2. Background ingestion uses the shared durable budget before writes. New indexes or larger batches require re-measuring D1 `meta.rows_written` and adjusting the reservation coefficient.
3. Preserve existing routes and fields; add optional version/base fields and capability gates for coordinated frontend releases.
4. Offline writes require idempotent server acknowledgement; conflicts remain queued until resolved. New entities extend the existing queue instead of adding another local database.
5. Additive migrations need a restore bookmark and preservation checks. Do not roll back to old public-config persistence: use a forward repair retaining private D1 config.

## Verification and limits

Automated coverage includes atomic budget competition/UTC reset, request identity isolation and JWT restrictions, private-copy-before-delete, bounded nonpersistent public cache, concurrent same-second note writes, rejection of false acknowledgements, quota batch stop, IndexedDB abort and v1 backup compatibility. Server/client/migrator types and Worker dry-run build are checked. Production acceptance results are recorded separately after publication.

See the stage-two dependency result below. Still outstanding: owner-authorized removal of the legacy public R2 config object (the user deferred this while unable to access the console), stronger session isolation on a dedicated same-site domain, distributed WAF/rate enforcement, restrictive frontend CSP with Markdown/media compatibility, and independent offsite backups and restore drills. These are separate work items; do not describe this release as a completed penetration test or a guarantee of zero vulnerabilities.

## Stage two: dependency and protocol hardening

- Upgrade Elysia to 1.4.30, CORS to 1.4.2, server timing to 1.4.1, Eden to 1.4.9, Drizzle ORM to 0.45.4, Mermaid within its existing 10.x line to 10.9.8, S3 SDK within 3.x to 3.1160.0, and Wrangler to 4.156.0. Apply compatible transitive patches and pin patched KaTeX, Prism, selector parser and YAML versions. R2 optional checksum negotiation is disabled to preserve S3-compatible behavior.
- Remove the incompatible `elysia-oauth2` wrapper; use the existing Arctic library directly for GitHub authorization. Keep the same endpoints, scopes, secure/HttpOnly/SameSite=Lax state cookie, state check, seven-day token format and frontend callback. Existing tokens remain valid. Adapt Eden's root methods without changing HTTP paths. Keep strict type checks; do not replace the API with untyped casts.
- Isolate environment/DB bindings with Workers-supported AsyncLocalStorage. Scope cache registries by environment with WeakMap; standalone test adapters retain Container fallback. Interleaved-request isolation is tested.
- Add a real streaming 6 MiB request bound alongside the cheap declared-size check. Upload file limit remains 5 MiB; WebSub raw bodies have a stricter 1 MiB bound. Keep upload authorization before parsing. Return 413 for actual overflow and generic server errors for internal diagnostics.
- Authenticate WebSub payloads using raw-body HMAC SHA-1/SHA-256 verification. Derive a separate per-subscription secret from the existing signing key with domain separation; no new credential is stored or exposed. Signed-lease callback keys start with `v2_`; renewal registers `hub.secret`, invalidates old leases until verification, and reacts to signing-key rotation. Unsigned/tampered callbacks cannot write RSS items. Old leases need renewal after deployment; daily polling remains available during this transition. No schema change is required.
- Renew push leases after deployment and after the daily job through a protected metadata-only endpoint, five sources per batch. This does not poll feeds or backfill content, and still works when a feed needs the metadata fallback. Actual renewals have a separate durable 1,000-unit/day budget; healthy signed leases are reused without writes. CI reports aggregate signed and verified counts, never callback keys or hub secrets.
- Add `scripts/audit-runtime.ts` to both release workflows. It resolves actual lockfile dependency paths and checks affected versions, rather than treating every developer-tool advisory as deployed code. The current static runtime closure has 566 nodes and zero matching advisories in the live Bun audit response. This is a known-advisory check, not proof that vulnerabilities do not exist. Five affected package names remain in developer-tool chains: basic-ftp, esbuild, extract-zip, ip-address and zod. Do not expose developer/test servers or run untrusted archive/proxy inputs. No published extract-zip fix was available in this scan; do not force incompatible Zod/FTP major overrides merely to hide warnings.
- Add full-framework OAuth/JWT/CORS/upload tests, real SQLite CRUD and private visibility tests through Eden, scoped writing-tag and backup compatibility checks, signed/forged/tampered WebSub route tests, streaming cancellation, formula sanitization, request isolation and audit-graph tests. All write tests use isolated fixtures, never production user records.

## Stage three: snapshot and retry correctness

- Read all fifteen backup collections, including feed/tag subqueries, in one D1 batch transaction rather than independent requests. Keep envelope v2, v1 compatibility, owner predicates, secret exclusions and encrypted download unchanged. This is a point-in-time cloud snapshot; it does not include unsynchronized local writes or uploaded image binaries. [D1 batch transaction semantics](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch).
- Concurrent todo, habit and daily-basics creation now acknowledges the existing owner-scoped ID after a unique-key conflict. Preserve the existing fast duplicate check, nullable operation keys and daily content uniqueness. Never acknowledge a failed insert without locating its saved record; otherwise return 409. No new schema, data cleanup or interface replacement.
- Follow a bounded, cycle-safe error cause chain when detecting D1 read/write quota exhaustion or background budget pauses. Drizzle wrapping must not turn a structured 503/Retry-After into an opaque 500 and recurring local retries. Client diagnostics remain redacted.
- The dependency gate validates command exit status and the full advisory JSON shape before using its result. A failed scan emitting valid JSON must stop publication. Runtime closure and developer-tool caveats from stage two remain applicable; no dependencies were upgraded in this stage.
- Regression exercises include same-key simultaneous creates, different-key identical daily items, edits immediately after snapshot commit, full real-row encrypted JSON round trips, wrapped quota handling through the framework, malformed audit responses and existing private/public API contracts. All writes use isolated memory fixtures. Encryption round trips are not an independent offsite backup or a production restore drill.
- Add optional capability fields `transactionalBackup`, `idempotentLifeCreates`, `wrappedQuotaErrors` without changing capability version 2 or existing routes. Production publication verifies the snapshot flag after edge propagation.
