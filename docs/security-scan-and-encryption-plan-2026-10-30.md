# 前后端安全复查与加密加固方案

日期：2026-10-30；基于 main 第三轮修补之后的源码复查及本轮回归。目的为保护现有数据、约束后台消耗、兼容未来模块，不调整主页面布局。

## 范围与方法

复查 Worker 入口、JWT/OAuth/访客登录、角色与记录所属人校验、文章/标签/评论、上传、SEO 代理、RSS 同步令牌/推送签名、配置缓存、备份、前端令牌保存与 Markdown/图表/数学渲染、离线数据、构建环境变量白名单与发布流程。使用隔离 SQLite、模拟网络、全量功能回归、生产构建、锁文件审计和发布后的轻量 HTTP 探测。没有执行压力测试、口令爆破、读取生产私密内容、云账号 IAM 全量审计或清理用户本地数据，因此不能据此保证不存在漏洞。

## 按风险排序的发现

| 优先级 | 问题和实际边界 | 处理状态 |
| --- | --- | --- |
| 高 | 旧 R2 公开配置副本仍是上轮明确遗留的问题。迁入 D1 并不会撤回旧链接；加密新数据也不能收回已公开内容。 | 用户已暂缓删除，本轮不绕过权限。恢复控制台操作后删除旧对象、失效缓存，并按实际字段判断是否需要轮换凭据。不要把配置内容写进工单或日志。 |
| 高 | 前端通过可读 Cookie 保存七天 Bearer 令牌；如果发生同源 XSS，令牌可能被取走。当前没有证明新的 XSS 利用链。 | 保留现有登录，避免突然失效；下一阶段改同站 API + HttpOnly 会话、服务端撤销与 CSRF 防护。 |
| 高，取决于私密图片使用 | 上传统一返回公开资源域名。私密日记页面的鉴权并不自动保护其图片链接，内容哈希文件名不是访问控制。 | 设计私有媒体存储与短时授权访问，先新上传、后逐批迁移旧引用；需要核对 R2 权限和保留恢复副本，不能直接把现有公开桶改成私有导致文章破图。 |
| 中 | SEO 使用路径拼接、跟随重定向，未校验 HTML 类型、限制上游响应或隔离脚本，并泄露异常文本。上游主机来自受信配置；这不等于已经证明任意目标 SSRF。 | 本轮修补目录边界、私密路由/配置扩展名限制、禁止重定向、超时和实际字节上限、HTML 类型校验、沙箱 CSP、统一错误。 |
| 中 | 访客登录失败计数先读后写，并发可少计次数；分布式来源可持续消耗 D1 写额度。 | 本轮增加原子五次/十五分钟计数和单独日预算，移除不可信 x-real-ip 回退；并发首次登录也不会创建多个访客身份。 |
| 中 | 评论已保存后，通知配置或网络失败仍让请求报错；用户重试可能重复评论。 | 本轮隔离可选通知失败，HTTPS、禁止重定向、五秒超时；不发送真实测试通知。没有新增通知队列，失败通知不会自动补发。 |
| 中 | 本地 IndexedDB 中的离线内容没有独立解锁密钥；同设备用户、恶意扩展或同源脚本有读取风险。 | 后续可选本地保险箱，必须保留离线队列和冲突恢复；仅把自动解密密钥放在同一个 localStorage 里不能解决这个威胁。 |
| 中 | 五个开发工具包仍有已知告警，SEO 手工任务还使用 Node 21 和未锁定 npx 下载入口。 | 本轮改 Node 22、先冻结安装，再调用锁定 Puppeteer CLI 并复用运行时审计门禁。五个包的升级仍待独立兼容性处理，不将告警忽略为已修复。 |

## 本轮可兼容落地的加固

- SEO 只读取指定缓存前缀。拒绝点段、反斜线、嵌套编码、私密页面和敏感查询参数；保留现有公开页面路径及 path&query 快照键惯例。上游只接受 HTML、最多 2 MiB、十秒超时，不跟随跳转；快照返回沙箱 CSP，禁止脚本、表单、插件和被其他页面嵌入。SEO 是静态快照，正常 Blog/Life 页面不使用这个沙箱。
- 访客登录每 IP 每十五分钟最多五次，包括成功尝试。每 UTC 日预留最多 1,600 安全预算单位，每次八单位，即最多 200 次进入数据库检查的尝试；实际消耗不是 Cloudflare 账号计量值。先用有界内存限流减少重复写，再用 D1 原子计数跨实例兜底。不同 IP 耗尽日预算时访客新登录会暂时被拒绝，GitHub OAuth 路由及已有有效令牌不受这个独立逻辑限制；账号总额度耗尽仍可能影响所有数据库操作。这个策略不能代替边缘 WAF。
- 访客仍使用原来的协作账号，这是有意保留的产品设计；共享口令意味着无法按自然人审计。未来采用每人独立邀请身份和可撤销权限，不在本轮把协作账户的数据拆分或搬家。
- 前端加入 no-referrer，以及 object-src/base-uri/form-action 基础 CSP。它不限制脚本加载，不能称为完整抗 XSS 策略，也不会阻止现有 Monaco、Mermaid、公式、图片和视频依赖。完整策略要先本地化或明确允许第三方脚本并做兼容验收。
- 新下载的备份升级为外层加密封装 v2：AES-256-GCM、随机 16 字节盐、随机 12 字节 IV、PBKDF2-HMAC-SHA256 600,000 次，并通过 AAD 认证版本与算法上下文。继续读取旧外层 v1/310,000 次的加密文件；内部个人数据格式仍为 v1/v2。只接受这两组已知参数，拒绝任意迭代次数，避免恶意文件触发无限计算。用户口令不上传服务器，不使用 JWT 签名密钥派生备份口令。提高成本不弥补弱口令，建议保管随机口令和独立副本。

## 加密方案与实施顺序

### 1. 现有传输、静态存储和备份

Cloudflare 文档说明 D1 提供平台静态加密及网络传输保护；这是平台能力说明，本轮没有访问控制台逐项核验账号配置。平台加密不防有权执行 SQL 的账号读取明文。下载备份由浏览器独立口令加密，本轮加强参数与版本认证，优先进行离线副本保管和恢复演练。

### 2. 会话与媒体边界先于数据库整体加密

建议使用自有同站域名部署前端/API，采用 Secure、HttpOnly、合理 SameSite 的会话 Cookie，并验证精确 Origin 和 CSRF 令牌。跨站 workers.dev + github.io 直接切 Cookie 可能被第三方 Cookie 限制，不能直接强制切换。会话保存服务端撤销标记、轮换和必要事件摘要；设置有界保留期，不记录口令、令牌、日记正文。先兼容旧 Bearer 并验证用户 ID 与离线命名空间，再按期限结束旧令牌支持。管理操作可增加重新认证。

私密媒体改用私有对象及短时访问授权。创建授权必须验证记录所属人；链接过期、跨账号拒绝、缓存 private/no-store、文章转公开等流程必须有集成测试。URL 签名不能代替私有桶，公开源链接也要撤销。

### 3. 可选服务端字段加密

如果需要降低数据库导出泄露影响，可对日记/备忘录正文采用 AES-256-GCM 信封加密。使用专门的密钥加密密钥，保存在 Worker Secret 或受控密钥服务，与 D1 和备份位置分离；密文带版本、keyId、随机 IV 和标签，AAD 包含账号、记录 ID、字段名与版本，防止调换密文。不得复用 JWT、访客口令或把密钥写进前端环境变量。

先增加可选密文字段，支持旧明文和新密文双读，恢复验证通过后逐批迁移；每批遵守 D1 写预算并记录恢复点。读取失败必须明确报错，不用空字符串覆盖旧内容。密钥轮换保留旧 keyId 到迁移和恢复验证结束。服务端可解密，所以这不是端到端加密。密钥托管、轮换与恢复责任确认前，不迁移生产正文。

### 4. 可选端到端/本地保险箱

若目标是服务器也不能读正文，则需要用户掌握的解锁密钥，客户端加密后同步密文。先做独立保险箱或可选私密模块，以便保持现有功能。正文全文搜索、后台自动处理、公开发布、跨设备解锁、协作共享及忘记口令恢复都需要重新设计。标签、时间、计数是否也加密要分别决定。IndexedDB 迁移应复制、校验、再切换，保留原队列；解密密钥只在解锁期间驻留内存，但已解锁页面的 XSS 仍可调用解密，因此渲染隔离和会话防护仍然必要。

## 后续验收条件

1. 旧公开配置与私密媒体原始链接均不能匿名读取；单独验证缓存失效。
2. 普通访客、共享协作者、Owner 的记录读取、修改、导出权限矩阵通过；不能只验证前端菜单隐藏。
3. 会话撤销后旧令牌立即拒绝，新会话继续访问原账号数据；离线队列不丢失。
4. 从加密副本在隔离环境恢复到一致记录数、标签关系与待办/番茄钟关联；验证错误口令、篡改、旧版本、缺失密钥和轮换场景。
5. 完整 CSP 先采集兼容结果，再逐步强制；写作、公式、图表、图片、RSS 视频及移动端通过。
6. WAF/限流规则按登录、上传、公开阅读、推送分别配置，避免把正常推送或私人同步误封；负载测试需独立窗口和预算。
